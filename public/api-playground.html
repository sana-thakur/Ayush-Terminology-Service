Compliance with India's 2016 EHR Standards

This prototype demonstrates key principles required for compliance with the Ayushman Bharat Digital Mission (ABDM) and India's EHR Standards.

OAuth 2.0–Secured Access using ABHA Tokens

OAuth 2.0 is the standard security protocol for granting access to APIs. In ABDM, every patient has an ABHA (Ayushman Bharat Health Account).

  • When an EMR system wants to access patient data, it must authenticate using ABHA-linked credentials to obtain a secure OAuth 2.0 token.
  • This token must be used in API requests (e.g., Authorization: Bearer <token>).
  • In this App: The /api/fhir/Bundle endpoint simulates this by requiring a Bearer token. While any token is accepted in this prototype, a real system would validate it against the ABDM gateway.
  • Administrator Governance: The /api/admin/* endpoints enforce admin authentication via Bearer token (default dev token: admin-secret-dev-token-2026).

Audit-Ready Metadata & Terminology Review Governance

Every access to patient data and every administrative review must be traceable. “Audit-ready” means the system automatically records metadata for every transaction.

  • Who: The identity of the reviewer, doctor, hospital, or system.
  • When: The exact ISO 8601 timestamp of the action.
  • What: The specific mapping state, fingerprint, or patient record accessed.
  • Why: The review reason category, clinical verification notes, or encounter purpose.
  • Version Binding: Verifications are bound to deterministic mapping fingerprints, flagging stale mappings if source data shifts.
